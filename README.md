# 🎯 코디세이 올인원 퀴즈

## 프로젝트 개요
코디세이 올인원 교육 과정에 관한 내용을 퀴즈로 풀어보는 콘솔 기반 퀴즈 게임입니다.  
퀴즈 풀기, 추가, 삭제, 수정, 목록 확인 기능을 제공하며,  
매 게임마다 닉네임, 점수, 타임스탐프를 기록합니다.  
프로그램을 종료해도 추가한 퀴즈와 모든 점수 기록이 유지됩니다.

**원격 저장소**: [GitHub - jil2fire/training-E1-2](https://github.com/jil2fire/training-E1-2)

---

## 클래스 설계 및 책임 분담

### 클래스별 주요 책임 (SRP - Single Responsibility Principle)

| 클래스 | 책임 | 주요 메서드 |
|--------|------|-----------|
| `Quiz` | 단일 퀴즈 문제 표현 및 정답 검사 | `display()`, `check_answer()`, `to_dict()`, `from_dict()` |
| `QuizGame` | 게임 전체 흐름 관리 (입력, 로직, 데이터 영속화) | `run()`, `play_quiz()`, `add_quiz()`, `load_data()`, `save_data()` |

### 로직 흐름 및 데이터 동기화

```
1️⃣  프로그램 시작
   └─ QuizGame 객체 생성
      └─ __init__() 호출
         └─ load_data() 실행
            └─ state.json에서 퀴즈 목록 & 최고점수 로드

2️⃣  메뉴 선택 (run() 메인 루프)
   ├─ 1: play_quiz() → 퀴즈 풀이 → 점수 기록 → save_data()
   ├─ 2: add_quiz() → 퀴즈 추가 → save_data()
   ├─ 3: delete_quiz() → 퀴즈 삭제 → save_data()
   ├─ 5: update_quiz() → 퀴즈 수정 → save_data()
   └─ 7: 종료 → save_data() 호출 후 exit

3️⃣  프로그램 종료 (안전 종료)
   ├─ 정상 종료: choice==7 → save_data() → break
   ├─ Ctrl+C: KeyboardInterrupt 예외 → save_data()
   └─ EOF: EOFError 예외 → save_data()
```

**저장 타이밍**: 데이터 변경 직후 + 프로그램 종료 시 (즉시 동기화)

## 퀴즈 주제 선정 이유
같은 코디세이 올인원 교육을 받고 있는 동료 교육생들에게 발표하는 자리인 만큼,  
모두가 직접 경험한 내용으로 공감대를 형성할 수 있는 주제를 선택했습니다.

---

## 설계 원칙: 추상화와 재사용성

### 왜 클래스를 사용했는가?

1. **추상화 (Abstraction)**
   - 퀴즈 한 문제를 `Quiz` 클래스로 추상화 → 복잡한 세부 사항을 숨김
   - 게임 로직을 `QuizGame`에 집중 → 비즈니스 로직이 명확

2. **재사용성 (Reusability)**
   - `Quiz` 객체는 `Quiz 목록 조회`, `퀴즈 풀이`, `퀴즈 수정` 등 다양한 곳에서 재사용
   - 메서드 분리로 각 기능이 독립적으로 호출 가능
   - 향후 다른 게임(OX퀴즈, 선택지 추가 등)에도 `Quiz` 클래스 활용 가능

### JSON 형식 선택 이유

| 측면 | JSON | XML | CSV |
|------|------|-----|-----|
| **가독성** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ |
| **한글 지원** | ✅ (UTF-8) | ✅ | △ (복잡) |
| **중첩 구조** | ✅ (자연스러움) | ✅ | ❌ |
| **파일 크기** | 작음 | 중간 | 작음 |
| **표준 라이브러리** | ✅ (`json`) | △ (`xml.etree`) | ✅ (`csv`) |
| **구조화도** | 높음 | 높음 | 낮음 |

**결론**: JSON은 계층적 데이터(퀴즈 목록, 점수 기록) 저장에 최적화되어 있으며, Python 표준 라이브러리로 쉽게 처리할 수 있습니다.

## 기능 목록

| 번호 | 기능 | 설명 |
|------|------|------|
| 1 | 퀴즈 풀기 | 등록된 퀴즈를 순서대로 풀고 최종 점수 확인 후 닉네임 입력 (1~20자) |
| 2 | 퀴즈 추가 | 문제·선택지 4개·정답 번호를 입력해 새 퀴즈 등록 (메뉴 복귀: `q` 입력) |
| 3 | 퀴즈 삭제 | 등록된 퀴즈 중 선택해서 삭제 (메뉴 복귀: `0` 입력) |
| 4 | 퀴즈 목록 | 현재 등록된 전체 퀴즈 목록 조회 |
| 5 | 퀴즈 수정 | 등록된 퀴즈 중 선택해서 문제·선택지·정답 수정 (메뉴 복귀: `0` 또는 `q` 입력) |
| 6 | 점수 확인 | 모든 점수 기록을 점수 높은 순서대로 조회 (닉네임, 점수, 날짜/시간 포함) |
| 7 | 종료 | 데이터 저장 후 프로그램 종료 |

### 닉네임 유효성 규칙

- **길이**: 1자 이상 20자 이하
- **허용 문자**: 한글, 영문(a-z, A-Z), 숫자(0-9), 언더스코어(_)
- **불허 문자**: 특수문자(!@#$%^&* 등), 공백만 사용

예시:
- ✅ 허용: `홍길동`, `Hong_Gildong`, `user123`, `_admin_`
- ❌ 불허: `홍 길 동`, `user!`, `user@`, `very_long_nickname_exceeds_20_characters`

## 데이터 파일 설명 (state.json)

- **경로**: 프로젝트 루트 (`./state.json`)
- **역할**: 퀴즈 목록, 최고 점수, 모든 게임의 점수 기록을 프로그램 종료 후에도 유지
- **생성 시점**: 프로그램 첫 실행 시 자동 생성
- **인코딩**: UTF-8

### 스키마
```json
{
    "quizzes": [
        {
            "question": "문제 텍스트 (str)",
            "choices": ["선택지1", "선택지2", "선택지3", "선택지4"],
            "answer": 1
        }
    ],
    "best_score": 0,
    "scores": [
        {
            "nickname": "닉네임 (str)",
            "score": 100,
            "timestamp": "2026-11-24 14:30:45"
        }
    ]
}
```

| 필드 | 타입 | 설명 |
|------|------|------|
| `quizzes` | list | 퀴즈 객체 목록 |
| `quizzes[].question` | str | 문제 텍스트 |
| `quizzes[].choices` | list[str] | 선택지 4개 |
| `quizzes[].answer` | int | 정답 번호 (1~4) |
| `best_score` | int | 최고 점수 (백분율, 0~100) |
| `scores` | list | 모든 게임의 점수 기록 목록 |
| `scores[].nickname` | str | 플레이어 닉네임 |
| `scores[].score` | int | 얻은 점수 (백분율, 0~100) |
| `scores[].timestamp` | str | 게임 완료 시각 (형식: `YYYY-MM-DD HH:MM:SS`) |

## 데이터 복구 및 백업 전략

### 현재 구현된 복구 메커니즘

| 오류 상황 | 현재 처리 | 한계점 |
|----------|---------|-------|
| **파일 없음** | 기본 퀴즈 6개로 초기화 | ✅ 정상 |
| **JSON 형식 오류** | 기본 퀴즈 6개로 초기화 | ⚠️ 기존 데이터 손실 |
| **파일 쓰기 실패** | 오류 메시지 출력 | ❌ 복구 불가 |
| **디스크 용량 부족** | 오류 메시지 출력 | ❌ 복구 불가 |

### 권장 개선 사항 (향후 버전)

1. **자동 백업 생성**
   ```
   저장 전: state.json → state.json.backup (매 저장 시)
   오류 발생: state.json.backup에서 복원
   ```

2. **버전 관리 백업**
   ```
   state.json.v1, state.json.v2, ... (최근 5개 버전 유지)
   ```

3. **재시도 메커니즘**
   ```
   파일 쓰기 실패 → 5초 대기 → 최대 3회 재시도
   ```

현재: **파일 손상 시 기본 퀴즈로 초기화되며, 추가한 퀴즈는 복구 불가능**

## 성능 분석

### 메모리 복잡도 (O 표기법)

| 작업 | 시간복잡도 | 공간복잡도 | 설명 |
|------|----------|----------|------|
| **파일 로드** | O(n) | O(n) | n: 퀴즈 개수 |
| **퀴즈 풀이** | O(n) | O(1) | 순서대로 순회 |
| **퀴즈 추가** | O(1) | O(1) | 리스트 append |
| **퀴즈 삭제** | O(n) | O(1) | 리스트 재정렬 |
| **점수 정렬** | O(m log m) | O(m) | m: 점수 기록 개수 |
| **파일 저장** | O(n+m) | O(n+m) | JSON 직렬화 |

### 대규모 데이터 처리 (1000개 이상 퀴즈)

#### 추정 성능

```
1000개 퀴즈 기준:

메모리 사용량:
  - 퀴즈 1개: ~200 bytes (문제 + 선택지 + 정답)
  - 1000개: ~200 KB
  - 충분히 작음 ✅

로드 시간:
  - JSON 파싱: ~1-2 ms (Python json 라이브러리)
  - Quiz 객체 변환: ~5-10 ms
  - 총 로드: ~10-15 ms ✅ (빠름)

풀이 시간:
  - 1000문제 순회: ~1-2초 (입력 대기 제외)
  - 점수 정렬 (1000 기록): ~O(m log m) ~20ms ✅

저장 시간:
  - JSON 직렬화: ~5-10 ms
  - 파일 쓰기: ~5-10 ms
  - 총: ~15-20 ms ✅
```

#### 결론

✅ **1000개 퀴즈도 무리 없이 처리 가능**
- 콘솔 입력이 병목(사용자 입력 대기)
- 프로그램 성능은 우수함

✅ **구현됨**:
- `KeyboardInterrupt` (Ctrl+C) 처리 → `save_data()` 호출
- `EOFError` (입력 스트림 종료) 처리 → `save_data()` 호출

⚠️ **미구현 (향후 개선)**:
- `SIGTERM` (Linux/Mac 종료 신호) 처리
- `SIGINT` (신호 핸들러 명시) 처리

### 권장 개선 (Unix 환경용)

```python
import signal

def handle_signal(sig, frame):
    print("프로그램이 종료됩니다...")
    game.save_data()
    exit(0)

signal.signal(signal.SIGTERM, handle_signal)
signal.signal(signal.SIGINT, handle_signal)
```
